bandit runs your existing coding agents — opencode, Claude Code, Codex, pi — on a kanban board with a mechanical verify gate, a consult thread that argues before it executes, and a ledger that remembers what actually worked.

Install in five commands Or let your agent do it Source

01 / INSTALL

Five commands, one dependency.

Bun is the only requirement. Your agents bring their own auth — bandit never sees or stores provider keys.

terminalmacOS / Linux
# 1. get bandit (Bun ≥ 1.4 is the only dependency)
git clone https://github.com/wisbech/bandit.git && cd bandit && bun install && bun run build
sudo ln -sf $PWD/bin/bandit.js /usr/local/bin/bandit

# 2. turn your project into a factory
$ cd your-project && bandit init

# 3. add a card (work = a card with acceptance criteria, not a chat)
$ bandit task "write a hello world module" --accept "module prints HELLO_WORLD"

# 4. run the factory (drains the board once; omit --once to watch forever)
$ bandit start --once

# 5. prove it — nine health checks, exit 1 on failure
$ bandit doctor && bandit watch

Local models, zero cloud tokens

The default config drives opencode through ollama (ollama/glm-5.3-flash:cloud). The full loop — actor, gate, grader, consults — runs without a single API key.

Or your existing subscriptions

Point the transport at Claude Code or Codex via ACP profiles; they use their own logins. bandit harnesses add registers any Anthropic-protocol endpoint (LiteLLM, gateways, ollama).

02 / WHY

Agents are powerful and unmanaged.

You babysit one session at a time, paste context by hand, and trust output nobody verified. bandit is the management layer: work becomes cards, claims become measurements, arguments become a record.

Cards instead of conversations

Every task has acceptance criteria and a budget. Done means the criteria were demonstrated — not that the agent said so.

Why: chat sessions lose the thread; cards are the thread.

The gate doesn't negotiate

The harness re-runs the actor's reported verification command and uses the actual exit code. Self-graded success is recorded as fiction when the gate disagrees.

Why: agents report exit code 0 optimistically; the machine that says done must not be the machine that did the work.

Arguments before tokens

Non-trivial cards get a consult: the critic argues the plan, the master decides, bad plans die before execution. Stuck cards get a "same wall or different wall?" conversation instead of a blind retry.

Why: the cheapest failure is one that never spent the compute.

A memory with provenance

The confidence ledger tracks which levers moved which measures, corroborated by independent evidence — Holland's bucket brigade running as credit assignment. Established means posterior probability (Thompson sampling when instruments converge) — not vibes, not folklore.

Why: "it worked last time" is not a number.

03 / HOW IT WORKS

Three organs, one boundary.

Measure, argue, decide — held by different organs so none can grade its own homework. The boundary exists because of Goodhart's law in RL: optimization pressure corrupts whatever it can reshape.

OrganRoleHard rule
Grader seatOne cheap call, criterion-by-criterion. Track record in .bandit/grading/.Never joins the room it grades; can't touch the gate.
Critic (peer)Argues free text in the consult thread at plan time, on stagnation, and at routing. Ends with one DECISION: line.Read-only. May SUMMON: a researcher or architect — spawned as a real child serf, audit in the registry.
MasterOwns the conversation and routing: retry, specialist, escalate.Decides with the thread in front of it; the thread is the receipt.
The gateRe-executes the actor's verification command; fingerprints repeated failures.Outside every conversation. No consult turns a red gate green.

The commands you'll actually type.

The factory improves itself — with evidence gates

After the board drains, the refiner reads failure signatures from the event log and proposes edits to serf prompts and memory — snapshot first, reversible via bandit refine --rollback. A factory that can't audit itself isn't running.

It ran on itself first

bandit's own board processed the features you're reading about. In production it found and fixed three of its own defects (a dead-end amend route, a false-red backtick bug, a blind stall-killer) — flagged a grading blind spot for a human, and the dossier narrated every round.

Compatibility

bandit drives opencode — OmO's host — as its default harness: run omo inside a bandit actor's workspace and the skills/kibitzer stack rides along. brigade gateways, herdr panes, and ACP adapters all attach as profiles. Complements, not competitors: OmO is a better agent; bandit is the factory that can tell you why it believes something.

Privacy

No telemetry, no accounts, no network calls of its own. Everything lives under your project's .bandit/; rm -rf .bandit deletes the factory cleanly. Your harnesses' provider traffic is between you and them.
